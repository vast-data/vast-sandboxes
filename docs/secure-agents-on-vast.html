Secure agents
VAST AI OS

The managed runtime runs the agent. VAST AI OS holds the state.

One prompt becomes a supervised multi-agent run. The managed runtime is OpenShell (the only way a sandbox is created), NemoClaw (the policy on that sandbox), and OpenClaw (the loop inside it). VAST AI OS is the platform underneath: workspace, corpus, and audit live on VAST, which is why the run can fan out, sleep, and still be cited.

Managed runtime

NVIDIA

OpenShell

The gate. Nothing else creates a sandbox.

  • One gateway per isolation boundary.
  • CreateSandbox mounts the VAST volume. It does not provision one.
  • Supervisor enforces the NemoClaw policy on process and egress.
  • Exec starts the agent. After keep-alive, the pod is deleted.
Inside the sandbox

The loop. One agent, one volume, one focus.

NVIDIA

NemoClaw

The rules. One blueprint, every sandbox in that boundary.

  • Blueprint and sandbox policy, applied once per isolation boundary.
  • Deny by default. Only named MCP tools are allowed through.
  • Egress is an allow-list: that boundary's MCP, the model endpoint, and VastDB.
  • The agent user is fixed. The volume is chowned to that user before start.

Platform

VAST AI OS

The platform under the managed runtime. Scale is a clone and a schema, not a copy of the data.

Block CSI

  • Head PVC per workflow, retained.
  • Zero-copy clone per sub-agent.
  • VolumeSnapshot before fan-out and again when the agent finishes.
  • Wake remounts the same volumes.

Identity and MCP

  • Sign-in is a VAST user through VMS.
  • The API scopes every request to one isolation boundary.
  • MCP is the only path from an agent to platform data.
  • The graph is rebuilt by reading spans, not by keeping the pod alive.

VastDB

The system of record. Agents write here directly. The UI only reads. There is no separate metrics stack.

Ground the answer

Corpus

The vector corpus agents search through MCP. A citation is real only when that search returns a hit. An empty result means the summary has nothing from VastDB to cite.

Show the run

Telemetry

Each sandbox writes its own spans. The graph and the token counts are a read of telemetry.spans, so they survive after the pod is gone.

Remember the workflow

Control

Workflows, turns, runs, and the versioned report. This is why sleep can delete the sandbox and the run still exists.

Keep boundaries apart

Memory

One schema per isolation boundary. Boundaries can share the corpus and still not share what their agents remember.

Sleep, then wake

The sandbox is temporary. The workspace, the checkpoint, and the audit stay on VAST AI OS, so the next turn remounts the same agent.

Sleep

OpenShell deletes the pod after keep-alive.

  • Sandbox and process are gone.
  • Head PVC and each agent clone stay, Retain.
  • VolumeSnapshots stay.
  • Spans, the summary, and the report stay in VastDB.
→Continue

Wake

The same volumes come back. A new turn starts.

  • PVCs are remounted. A missing volume is restored from its snapshot.
  • OpenClaw session files on the PVC resume the conversation.
  • New run, new fan-out, new summary. History keeps the earlier turn.

Prompt

A signed-in user submits one prompt. The control plane lives outside the sandbox. It does not run inside one.

Policy once, sandboxes many

NemoClaw is attached to the isolation boundary, and OpenShell enforces it on every CreateSandbox. Adding a sub-agent does not add a new security review.

Fan-out is a clone

AI OS clones the head volume per agent. The corpus stays in VastDB. Parallel agents do not each receive a copy of the data.

Sleep does not lose the agent

OpenShell can delete every sandbox. Wake does not rebuild state: AI OS remounts the PVCs, and the graph is already in VastDB.
